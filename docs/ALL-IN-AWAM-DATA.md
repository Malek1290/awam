# كل حاجة في جدول واحد: `awam-data`

> **التاريخ:** 31 أكتوبر 2026
> **الاختبارات:** **85 ✅ / 0 ❌** (`cd tests && npm test`)

---

## الفكرة في سطر

قبل كده كان فيه **٣ جداول** بيتشاركوا مع مشروع تاني (`orders` · `coupons` · `awam_settings`).
دلوقتي **كل حاجة في جدول واحد اسمه `awam-data`**، والعمود **`kind`** هو اللي بيفرّق بين الصفوف:

| `kind` | إيه ده | بيتكتب من |
|---|---|---|
| `product` | منتج | لوحة التحكم |
| `order` | طلب عميل | صفحة إتمام الطلب |
| `coupon` | كود خصم | لوحة التحكم |
| `setting` | إعدادات الشحن | لوحة التحكم |

يعني: **مفيش أي جدول مشترك مع Clothina أو أي موقع تاني** — ولا للقراءة ولا للكتابة.

---

## الخطوة المطلوبة منك (مرة واحدة)

**Supabase → SQL Editor → New query → الصق الملف ده كله → Run**

```
supabase-update-5-all-in-awam-data.sql
```

الملف بيعمل ٦ حاجات:

1. **يضيف عمود `kind`** + أعمدة الطلبات (الاسم، التليفون، العنوان، الإجمالي…) وأعمدة الكوبونات (الكود، النسبة، التفعيل، تاريخ الانتهاء…) وأعمدة الإعدادات (key/value).
2. **يعلّم كل الصفوف الموجودة `kind = 'product'`** — منتجاتك الحالية زي ما هي، مفيش أي مسح. وكمان بيفكّ أي قيد `NOT NULL` قديم على أعمدة المنتجات (زي السعر/العنوان) عشان صفوف الطلبات تدخل من غير مشاكل.
3. **فهارس** عشان القراءة تفضل سريعة: على `kind`، وعلى `(kind, key)` للإعدادات، وعلى `code` للكوبونات (منع تكرار الكود)، وعلى تاريخ الطلبات.
4. **دالة آدمن خاصة بعوام** (`awam_is_admin()`): بتقرا هيدر `x-jl-admin` اللي الموقع بيبعته — مش بتعتمد على دالة أي مشروع تاني.
5. **سياسات RLS**:
   - الزائر يقدر **يقرا**: المنتجات + الكوبونات المفعّلة + الإعدادات.
   - الزائر **مش** يقدر يقرا **الطلبات** (بيانات عملاء) — دي للآدمن بس.
   - الزائر يقدر **يضيف طلب** بس (ده اللي بيحصل وقت الشراء).
   - التعديل والحذف: الآدمن بس.
6. **دالة تحقق من الكوبون** (`awam_validate_coupon`) + **٣ فيوهات للراحة** في لوحة Supabase (`awam_products` / `awam_orders` / `awam_coupons`) بتخليك تشوف كل نوع لوحده مع إنهم في نفس الجدول.

**الملف آمن:**
- ينفع تشغّله أكتر من مرة.
- مفيش فيه `DROP TABLE` ولا `DELETE` ولا `TRUNCATE`.
- مش بيغيّر أي صف موجود غير إنه يضيف `kind = 'product'`.

## قبل ما تشغّله — الموقع شغال عادي؟

أيوه. الكود فيه **وضع احتياطي**:

| الحاجة | قبل تنفيذ الـ SQL | بعد تنفيذ الـ SQL |
|---|---|---|
| المنتجات | بتتقري من `awam-data` (كل الصفوف = منتجات) | بتتقري بـ `kind = product` |
| الطلبات | بتتجمع في طابور جوه المتصفح وتتحاول تتحفظ تاني أول ما الجدول يشتغل — **مفيش كتابة في أي جدول تاني** | بتتحفظ في `awam-data` بـ `kind = order` |
| الكوبونات | بتتحقق من الدالة القديمة/الجدول القديم | بتتحقق من `awam-data` |
| إعدادات الشحن | بتتقري من `awam_settings` | بتتقري وتتحفظ في `awam-data` |

أول ما تشغّل الملف، كل حاجة تتحوّل تلقائيًا للجدول الجديد — **من غير أي تعديل في الكود**.

## اللي هتشوفه في لوحة تحكم Supabase

جدول `awam-data` واحد فيه كل حاجة، وعمود `kind` بيقولك كل صف إيه:

```
kind      | title / code   | price | total | phone        | created_at
----------|----------------|-------|-------|--------------|-------------
product   | عباية «ندى»     | 2200  |       |              | 2026-10-20
product   | دلنجت «ليالي»   | 3600  |       |              | 2026-10-21
coupon    | EID20          |       |       |              | 2026-10-22
order     | AW-1042        |       | 4350  | 01129196650  | 2026-10-31
setting   | shipping       |       |       |              | 2026-10-19
```

ولو عايز تشوف نوع لوحده، استخدم الفيوهات:

```sql
select * from awam_products order by sort;
select * from awam_orders  order by created_at desc;
select * from awam_coupons;
```

## في لوحة التحكم (الموقع)

- **تاب الطلبات**: بيقرا `kind = order` من `awam-data` — أول طلب جديد هيظهر تلقائيًا.
- **تاب الكوبونات**: إضافة/تعديل/حذف كوبون بيتم في `awam-data` بـ `kind = coupon`. العميل بيكتب الكود في صفحة إتمام الطلب، والتحقق بيحصل من نفس الجدول.
- **تاب الإعدادات**: حفظ أسعار الشحن بقى بيكتب صف `kind = setting` و`key = shipping` (بقى مفيش جدول `awam_settings`).
- **تاب المنتجات**: بيقرا ويكتب `kind = product` بس — فمش هيظهرلك كوبون أو طلب وسط المنتجات.

## لو الكوبونات القديمة عايزة تفضل

الكوبونات القديمة موجودة في جدول `coupons` المشترك. لو عايز تنقلها:

```sql
-- اختياري: نقل الكوبونات القديمة (شغّله مرة واحدة)
insert into public."awam-data" (kind, code, percent, active, starts_at, ends_at, product_ids)
select 'coupon', code, percent, active, starts_at, ends_at, coalesce(product_ids, '[]'::jsonb)
  from public.coupons
 where code is not null
on conflict do nothing;
```

> لو الجدول ده فيه كوبونات موقع تاني، استخدم `where` تختار كوبوناتك بس.

ونفس الفكرة للطلبات القديمة — موجودة كبلوك **معلّق** في آخر ملف الـ SQL (مش بيشتغل لوحده عشان ماينقلش طلبات موقع تاني).

### الاختبارات الجديدة (17)

- الإعدادات بتوجّه الأربعة على `awam-data`.
- مفيش أي كتابة/قراءة من `orders` أو `coupons` في الكود.
- الطلب بيتحفظ بـ `kind = order`.
- ملف SQL فيه العمود والبوليسي والدالة، ومفيش فيه أوامر خطرة، ومش بيلمس الجداول المشتركة.
- الطلبات والكوبونات **مش** بتظهر كمنتجات في المتجر.
- فلتر المنتجات بيتبعت للسيرفر بـ `kind = product`.
- **قبل** تشغيل الـ SQL الموقع بيكمل شغل (الوضع الاحتياطي).
- لوحة التحكم: الطلبات بتظهر من `awam-data` · إضافة كوبون بتتحفظ بـ `kind = coupon` · حفظ الشحن بيكتب `kind = setting`.
- الشيك آوت: كوبون بيتخصم صح · لو الدالة لسه مش متعملة بيتحقق من صفوف الجدول · الكوبون المتوقف بيترفض.
- لو حفظ الطلب فشل: الطلب بيتخزن في المتصفح (مش في جدول `orders` المشترك)، وأول زيارة بعدها بتحاول تحفظه تلقائيًا في `awam-data`.

## ملاحظة أمان مهمة

الطلبات بقت في نفس جدول المنتجات، فلو الجدول كان مفتوح للقراءة العامة، **بيانات العملاء هتكون مكشوفة**. عشان كده سياسة القراءة بتاعتنا بتسمح بـ:

```sql
kind is null or kind = 'product' or kind = 'setting'
or (kind = 'coupon' and active = true)
or awam_is_admin()
```

يعني الطلبات (`kind = 'order'`) **مش بتظهر لأي زائر** — لا من الموقع ولا من REST API — إلا لو الطلب جاي بهيدر الآدمن.
